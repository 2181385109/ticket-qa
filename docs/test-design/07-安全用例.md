# 07 · 安全用例

方法:**等价类划分**(注入点 × 载荷类型)、**判定表**(越权,见 04)、**探测**(敏感信息:先测事实再定期望)。

安全用例和功能用例的区别只有一个:功能用例问"正确的输入能不能得到正确的结果",安全用例问"错误的输入能不能得到错误的结果"。
所以安全用例的断言重点是**没有副作用**——状态没变、表没少、文件没逃出目录——而不只是状态码。

越权(水平 / 垂直)的完整判定表在 [04-权限判定表](04-权限判定表.md),附件绕过在 [05-附件等价类划分](05-附件等价类划分.md),这里不重复。

## 1. SQL 注入探测——按注入点分等价类

MyBatis-Plus 全部 `#{}` 预编译,预期是"载荷当普通文本"。每个注入点一个等价类,每类取经典载荷:

| 注入点 | 类型 | 载荷代表 | 期望 | 断言 | 用例 |
|---|---|---|---|---|---|
| JSON 字符串字段(title / content) | 字符串 | `' OR '1'='1`、`'; DROP TABLE ticket; --`、UNION SELECT、`' AND SLEEP(5) --`、URL 编码、十六进制、反斜杠 | 201,原样存取 | 响应和库里的 title == 载荷;ticket 总数 +1;agent 仍 6 行;耗时 < 4s;update 同样参数化 | `test_string_fields_are_parameterised`(10 个载荷) |
| 查询参数 status(枚举) | 类型绑定 | `PENDING' OR '1'='1`、`;DROP`、UNION | 400 / 40001(枚举转换拒绝) | 不是 500 | `test_status_param_is_enum_bound` |
| 路径参数 id(Long) | 类型绑定 | `1 OR 1=1`、`1'`、`-1`、溢出、`1.0`、`%00` | 400 或 404,不是 500 | `%00` 由 Tomcat 拦(HTML 400,无信封,KI-005) | `test_path_id_is_typed` |
| 路径参数尾巴 | 框架容错 | `;DROP TABLE ticket`、`%0a`、`%20` | 被剥掉 / trim,等价于原 id(观察项 KI-005) | 200 时 id 正确;表不变 | `test_path_id_tolerated_suffixes` |
| 分页参数 page / size(long) | 类型绑定 | `1 OR 1=1`、`10; DROP`、`1'` | 400 | | `test_paging_params_are_typed` |
| assigneeId(Long) | 类型绑定 | `3 OR 1=1` | 400 | | `test_assignee_id_is_typed` |
| X-User-Id 头 | 类型绑定 | `3 OR 1=1`、`3' --`、`1; DROP` | 401(解析失败),不会变成别的用户 | | `test_user_header_injection` |
| 时间盲注 | | SLEEP(5) 在 title / content | 响应 < 4s | | `test_no_time_based_injection` |

"不是 500"是所有注入用例的底线:500 说明载荷进入了 SQL 语法或引发了未处理异常。

## 2. 认证头与角色伪造

| 类 | 代表 | 期望 | 用例 |
|---|---|---|---|
| 缺失 / 空 / 非数字 / 不存在 / 负数 / 0 | | 401 / 40101,统一信封 | `test_missing_header`、`test_invalid_header_values`、`test_unknown_user` |
| 逗号多值、制表符 | `3, 1`、`3\t1` | 401(不会被解析成其中一个) | `test_user_id_header_tricks` |
| 角色通过 query / 额外头 / body 注入 | `?role=ADMIN`、`X-Role: ADMIN`、body `{"role":"ADMIN"}` | 仍按 X-User-Id 的真实角色判定 → 40302 | `test_role_cannot_be_injected` |

已知设计边界(ADR-007):X-User-Id 本身是可信头、没有签名。这不是漏洞而是测试系统的鉴权简化,用例不测"伪造 X-User-Id",测的是伪造之外的东西。

## 3. 敏感信息——探测

规格没有要求脱敏,所以先把事实测出来,再把期望挂成 xfail(ADR-014):

| 用例 | 性质 | 结果 |
|---|---|---|
| `test_current_behaviour_phone_is_plain` | 事实记录 | 创建响应 / 详情 / 列表 / 库表 四处手机号明文(通过) |
| `test_pii_is_sent_to_llm` | 事实记录 | 分类请求和草稿请求把含手机号的原文发给了 LLM 挡板(通过)——真实模式下即出境 |
| `test_detail_masks_phone` | 期望 | 详情脱敏成 `138****5678` → xfail strict(KI-001) |
| `test_list_masks_phone` | 期望 | 列表脱敏 → xfail strict(KI-001) |

## 4. 越权——IDOR 扫描(补充 04)

| 用例 | 做法 | 期望 |
|---|---|---|
| `test_every_endpoint_rejects_non_owner` | 7 个带 id 的接口 × 3 个入侵者身份 | 全部 403 / 40301;工单状态、assignee、标题、审计条数、附件都不变 |
| `test_id_enumeration_sweep` | agent_a 遍历自己工单 id 附近 ±2 的所有 id | 只有自己的 200,其余 403/404,`data` 为空,响应文本不含 `title`(不泄露存在性之外的信息) |
| `test_list_does_not_leak` | 列表 + status 过滤 | 别人的 id 不出现 |
| `test_pending_ticket_visibility` | 同组 PENDING 单 | 抢之前 403,抢之后 200,原来的坐席 403 |

## 5. 未覆盖、留待后续的

- XSS:接口只返回 JSON,没有 HTML 渲染面;平台层(第三阶段)出现前端时再补。
- CSRF:无 Cookie 会话,不适用。
- 限流 / 暴力枚举:规格没有,不测。
- 附件下载接口不存在,所以"下载时的 Content-Disposition 注入"没有载体。

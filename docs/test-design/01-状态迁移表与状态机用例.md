# 01 · 状态迁移表与状态机用例

方法:**状态迁移法**(主)+ **边界值分析**(重开窗口)。

为什么用状态迁移法:状态机的规格本身就是一张表(CLAUDE.md §5.1),表里每一格 (from, to) 要么合法要么非法,
没有第三种。把表画全,每一格就是一条用例——不需要"挑"用例,也不会漏。非法格的数量(25)远多于合法格(11),
所以"只测合法路径"会漏掉 70% 的行为;这正是数据驱动状态机(ADR-001)的价值:用例可以从数据推导。

## 1. 状态迁移表

行 = 当前状态(from),列 = 目标状态(to)。`✓` 合法,`✗` 非法,`✓*` 合法但有守卫。

| from \ to | PENDING | ASSIGNED | PROCESSING | WAIT_CONFIRM | CLOSED | ESCALATED |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| **PENDING** | ✗ | ✓ | ✗ | ✗ | ✗ | ✓ |
| **ASSIGNED** | ✓(退回) | ✗ | ✓ | ✗ | ✗ | ✓ |
| **PROCESSING** | ✗ | ✗ | ✗ | ✓ | ✗ | ✓ |
| **WAIT_CONFIRM** | ✗ | ✗ | ✓(用户不认可) | ✗ | ✓ | ✗ |
| **CLOSED** | ✗ | ✗ | ✓*(重开,≤ 7 天) | ✗ | ✗ | ✗ |
| **ESCALATED** | ✗ | ✓ | ✗ | ✗ | ✗ | ✗ |

合计 36 格:**11 合法(含 1 个带守卫)、25 非法(含 6 个自环)**。

事实来源:`service/src/main/java/com/ticketqa/statemachine/TransitionTable.java` 的 `EDGES`。
测试里的表是**独立抄本**(`TransitionTableTest.SPEC`、`test_state_machine.py::SPEC`),故意不引用实现——
引用实现等于拿实现测实现,规格改了测试不会响。

### 每条边的附带行为(进入动作 / 守卫)

| 边 | 守卫 | 进入动作 | 谁能触发 |
|---|---|---|---|
| PENDING → ASSIGNED | 必须带 assigneeId,坐席与工单同组 | — | 抢单:本组任何人;指派:LEADER 本组 / ADMIN |
| PENDING → ESCALATED | — | — | 人工:写权限;自动:SLA 扫描 |
| ASSIGNED → PROCESSING | — | — | 写权限 |
| ASSIGNED → PENDING | — | **assigneeId 清空** | 写权限 |
| ASSIGNED → ESCALATED | — | — | 写权限 / SLA 扫描 |
| PROCESSING → WAIT_CONFIRM | — | — | 写权限 |
| PROCESSING → ESCALATED | — | — | 写权限(SLA 扫描不扫 PROCESSING) |
| WAIT_CONFIRM → CLOSED | — | **closedAt = now** | 写权限 |
| WAIT_CONFIRM → PROCESSING | — | (closedAt 不变,仍为空) | 写权限 |
| CLOSED → PROCESSING | **closedAt + 7d ≥ now(闭区间)** | **closedAt 清空** | 写权限 |
| ESCALATED → ASSIGNED | 同 PENDING → ASSIGNED | — | LEADER 本组 / ADMIN(不能抢) |

## 2. 从表推导的用例

### 2.1 非法流转:25 格逐格(不挑)

推导规则:`for from in 状态: for to in 状态: if to not in SPEC[from]: 一条用例`。

每条用例的断言(三层都一样):
1. 抛 `IllegalTransitionException` / HTTP 409 + 40901,异常(message)里带 from 和 to
2. 工单状态不变
3. 没有落库、没有审计、没有事件(单测 verify never;接口层比较审计条数)

| 层 | 文件 | 备注 |
|---|---|---|
| 单测 | `TransitionTableTest.illegalTransitionsRejected`(25 条参数化) | 纯对象,毫秒级 |
| 单测 | `TransitionTableTest.selfLoopsAreIllegal` | 6 个自环单独再断一次 |
| 接口 | `test_state_machine.py::TestIllegalTransitions::test_illegal_cell`(25 条参数化) | 工厂把工单造到 from 状态(走真实接口链,ESCALATED 经 SLA 扫描),目标 ASSIGNED 用 LEADER + assigneeId 发,其余用 ADMIN,排除权限因素 |

### 2.2 合法流转:11 条边每条至少一次

| 用例 | 覆盖的边 | 层 / 文件 |
|---|---|---|
| 主干路径:PENDING→ASSIGNED(抢)→PROCESSING→WAIT_CONFIRM→CLOSED→PROCESSING(重开) | 5 条 | 单测 `TicketStateMachineTest.fullHappyPath`;接口 `test_main_path_with_audit`(同时核对审计逐条) |
| 退回:ASSIGNED→PENDING,assignee 清空,别人可再抢 | 1 | 单测 `enteringPendingClearsAssignee`、`TicketServiceTest.agentReturnsTicketToPending`;接口 `test_return_to_pending_clears_assignee` |
| 用户不认可:WAIT_CONFIRM→PROCESSING,closedAt 仍空 | 1 | 单测 `rejectFromWaitConfirmKeepsFields`;接口 `test_customer_rejects` |
| 人工升级:PENDING / ASSIGNED / PROCESSING → ESCALATED | 3 | 接口 `test_manual_escalate`(参数化 3 个起点) |
| 升级后指派:ESCALATED→ASSIGNED,抢单被拒 | 1 | 单测 `TicketServiceTest.assignEscalated`;接口 `test_escalated_back_to_assigned` |
| 11 条边的通用放行 | 11 | 单测 `TransitionTableTest.legalTransitionsPass`(参数化) |

### 2.3 守卫:重开 7 天窗口——边界值分析

规格"限 7 天内",实现是闭区间 `closedAt + 7d ≥ now`(与 ADR-006 的闭区间约定一致)。
输入域是 `now - closedAt`,有序,取边界点和 ±1:

| 点 | now - closedAt | 期望 | 用例 |
|---|---|---|---|
| 下界 | 0(刚关就重开) | 允许 | `reopenImmediatelyAllowed` |
| 上界 − 1s | 7d − 1s | 允许 | `oneSecondInsideWindowAllowed` |
| **上界** | **7d 整** | **允许(闭区间)** | `exactlySevenDaysAllowed` |
| 上界 + 1ms | 7d + 1ms | 拒绝 | `oneMillisecondOutsideWindowRejected` |
| 上界 + 1s | 7d + 1s | 拒绝,消息含"7 天" | `oneSecondOutsideWindowRejected` |
| 无效输入 | closedAt 为 null | 拒绝,消息含"关闭时间" | `missingClosedAtRejected` |

接口层对真库只能到分钟级精度(改 `closed_at` 列):6.9 天允许、7 天零 1 分钟拒绝(`TestReopenWindow`)。
毫秒级边界由单测负责——这是两层分工的原则:**精度归单测,集成归接口**。

### 2.4 进入动作

| 动作 | 用例 |
|---|---|
| 进入 CLOSED 记 closedAt = now | `enteringClosedStampsClosedAt` |
| 重开清 closedAt | `reopenClearsClosedAt`;接口主干路径断 `closedAt` 键消失 |
| 进入 PENDING 清 assignee | 见 2.2 退回 |
| 进入 ASSIGNED 没有动作(assignee 由 Service 设) | `enteringAssignedHasNoAction` |
| transit 返回流转前状态(给审计写 from) | `transitReturnsPreviousStatus` |

## 3. 表本身的健全性

| 用例 | 断什么 |
|---|---|
| `edgesMatchSpecExactly` | 实现的 EDGES 与规格抄本逐行相等,边数 = 11 |
| `noDeadStates` | 每个状态都有出边(没有进得去出不来的状态);CLOSED 只能重开,ESCALATED 只能被指派 |

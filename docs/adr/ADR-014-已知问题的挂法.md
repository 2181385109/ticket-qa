# ADR-014: 测出来的缺陷用 xfail(strict) 挂在套件里,不修、不删、不 skip

## 背景

本阶段的原则是"发现 bug 记进 known-issues,不要顺手修",同时收口时不能留失败或无说明的 skip。
两条放在一起就有一个必须回答的问题:**一条已知会失败的用例,放在套件里的什么位置?**

实际测出来的(docs/findings/known-issues.md):手机号未脱敏(KI-001)、polyglot 附件被接受(KI-002),
以及几条不是缺陷的观察项(KI-003~007)。

## 选项

- **方案 A:删掉用例,只在 known-issues 里记一笔**
  代价:套件里没有它,缺陷修没修、有没有回归,套件不知道。记录和代码脱钩,过三个月没人记得。

- **方案 B:`@pytest.mark.skip`**
  代价:skip 的语义是"没跑",报告里是一片黄;缺陷修好了它也不会变绿,永远躺在那。
  收口要求明确不许 skip。

- **方案 C:让它失败,CI 红着**
  代价:红成常态之后,真正的新失败没人看;"CI 跑绿"这个目标直接不成立。

- **方案 D:`@pytest.mark.xfail(strict=True, reason="KI-xxx …")`** ← 采用
  做法:用例照写"应该的行为",打 xfail。当前失败 → XFAIL,套件绿;
  服务某天改对了 → XPASS,`strict=True` 让 XPASS 算失败 → CI 红,提醒把 xfail 摘掉、把 known-issues 更新。
  再加一个 `known_issue` 自定义标记,`pytest -m known_issue` 能单独列出全部已知问题。
  代价:报告里 XFAIL 是一种"特殊的绿",看报告的人要懂这个语义;reason 里必须写 KI 编号,否则对不上记录。

## 决定

方案 D。配套规则:

1. **只有确认是缺陷或缺失需求的才挂 xfail**;"框架就是这样"的观察项(矩阵变量剥离、惰性指标)不挂,
   用例按当前行为断言,标题里写明"观察项"。
2. xfail 用例旁边必须有一条**通过的**"事实记录"用例(比如 `test_current_behaviour_phone_is_plain`),
   把当前行为断出来——这样 xfail 用例表达"应该",事实用例表达"现在",两条一起才是完整记录。
3. `reason` 以 KI 编号开头,known-issues.md 里每条写清对应的用例 id,双向可查。

## 后果

- 接受了:Allure 把 pytest 的 xfail 计成 **skipped**(本地报告首页:284 passed / 3 skipped / 0 failed),看报告的人要知道这 3 个 skipped 是已知问题而不是没跑;`pytest -m known_issue` 能列出它们。
- 接受了:`strict=True` 意味着修好缺陷的那个提交会先把 CI 弄红,修的人必须同时摘 xfail——
  这是刻意的,它逼着"修代码"和"更新记录"在同一个提交里。
- 什么场景下这个选择是错的:如果缺陷数量涨到几十条,xfail 会淹没报告,那时应该把已知问题拆成独立的
  `pytest -m known_issue` job 单独跑、单独看,主流水线只跑非 known_issue。

## 常见质疑与回应

**"测出 bug 为什么不直接修?"**
> 这个阶段的职责是建测试体系,不是改被测服务;两件事混在一个提交里,review 的人分不清哪些是测试哪些是修复。
> 更实际的原因:手机号要不要脱敏、在哪一层脱敏(接口层还是入库前),是产品决策,不是测试能替它做的。
> 我的交付是"把它测出来、记下来、挂在套件里让它不会被忘掉"。

**"xfail 和 skip 有什么本质区别?"**
> skip 是"不执行",xfail 是"执行并且预期失败"。区别在缺陷修好那天:skip 的用例继续 skip,没人知道它其实能过了;
> xfail(strict) 的用例会 XPASS 变红,强迫你摘掉标记。前者让已知问题永远躺着,后者让它有闭环。

**"CI 上 3 个 XFAIL 算不算绿?"**
> 算,而且是有信息的绿:它告诉你"套件知道这三个问题,且它们还没修"。全绿零 XFAIL 才可疑——要么没测出问题,
> 要么测出来删掉了。报告首页的 XFAIL 数就是当前已知问题数,和 known-issues.md 里的条目一一对应。

**替代方案**(以上是默认选择,可按需改)
> 如果认定脱敏不是需求,把 `test_pii_masking.py` 里两条 xfail 用例删掉、known-issues 里 KI-001 改成"决定不做",
> 留下那条事实记录用例即可。

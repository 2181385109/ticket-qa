# ADR-010: 只装技术栈表里的依赖——为什么没有 Lombok、Spring Security、Resilience4j、MapStruct、Outbox 框架

## 背景

CLAUDE.md §3 锁定了技术栈,并要求"只装列出的依赖"。Spring Boot 项目里有几个几乎是
条件反射会加的库,这里都没加。每一个都会被问"为什么不用 X",集中记一条。

## 选项与决定(逐个)

### Lombok

- 加:实体 / DTO 少写 70% 的样板代码。
- 不加 ← 采用:
  - 读者是 Java 弱项的人。`@Data` 把 getter / setter / equals / hashCode / toString 全藏起来,
    读者看不到 MyBatis-Plus 是靠 setter 反射填值、Jackson 是靠 getter 序列化的。
    显式代码让"框架到底调了什么"可见。
  - 不可变数据用 Java 17 的 **record**(`Result<T>`、所有 DTO、`CurrentUser`、事件、Outcome),
    一行声明,零样板,而且是语言特性不是注解处理器。
  - 只有 MyBatis-Plus 实体和 Redis 缓存对象需要可变 POJO,6 张表 6 个类,getter / setter
    用脚本一次生成,之后几乎不改。
  - 代价:实体类 150 行,视觉上啰嗦。

### Spring Security

不加,见 ADR-007。一句话:被测点是授权逻辑不是认证强度,`X-User-Id` 头让安全用例可以
扮演任何角色。

### Resilience4j / Sentinel

不加,见 ADR-004。一句话:规格只要"连续 5 次失败打开 60 秒"一种策略,40 行自写熔断器
每一行都能在白板上解释;Resilience4j 的滑动窗口 + 失败率 + 半开是另一套语义,参数十几个,
调完行为还不一样。Sentinel 在 CLAUDE.md §3 明确禁止。

### MapStruct

- 加:实体 ↔ VO 转换自动生成。
- 不加 ← 采用:两个转换方法各 3 行(`TicketConverter`),手写比配注解处理器快;
  MapStruct 生成的代码在 `target/` 里,读者看不到、说不清"这个字段是怎么映射的"。

### Outbox / 本地消息表框架(或 RocketMQ 事务消息)

不加,见 ADR-002。一句话:三类消息都是通知,丢了不产生错误数据;用 AFTER_COMMIT +
可观测的失败指标,把"可能丢"作为已知取舍记录下来。

### Spring StateMachine

不加,见 ADR-001。一句话:6 个状态一张 EnumMap,框架的异步事件和状态持久化是负担。

### Apache Tika

不加,见 ADR-008。一句话:白名单 4 种格式 3 条魔数,40 行;Tika 是黑盒。

### Testcontainers / 进程内 WireMock

本阶段不加(没有测试代码)。下一阶段(测试)会评估:单测层用 MockRestServiceServer 还是
进程内 WireMock,集成测试用 Testcontainers 还是复用 docker-compose。到时另开 ADR。

### 加了但值得说明的

| 依赖 | 为什么 |
|---|---|
| `spring-boot-starter-cache` | 它是 Spring Boot 自带模块不是第三方库;用它让 Redis 有一个真实用途(坐席快照缓存),并且给出 `@Cacheable` 代理失效的教学案例(`AgentCache` 为什么是独立 Bean) |
| `spring-rabbit-test`(test scope) | 下一阶段测消费者幂等用,现在先声明 |
| `jacoco-maven-plugin` | 技术栈表里有;本阶段只挂 agent 和出报告,门禁阈值和它的 ADR 放到测试阶段 |
| `mybatis-plus-spring-boot3-starter` 3.5.7 | 3.5.9 起分页插件拆成独立的 `mybatis-plus-jsqlparser` 模块,3.5.7 是最后一个"一个依赖就能分页"的版本,少一个坑 |
| Spring Boot 3.3.5 | 3.3 线和 MyBatis-Plus 3.5.7 是验证过的组合;3.4+ 的 `mybatis-spring` 版本变化有兼容性报告,不在本项目冒这个险 |

## 后果

- 接受:实体类啰嗦。
- 接受:没有 Lombok 意味着不能用 `@Slf4j`,每个类手写
  `private static final Logger log = LoggerFactory.getLogger(X.class)`——一行,能接受。
- 接受:版本不是最新。Spring Boot 3.3 系列已停止 OSS 支持,生产升级需要重新验证
  MyBatis-Plus 兼容性。
- 什么场景下会是错的:团队协作、实体上百个——那时 Lombok / MapStruct 省下的时间是实打实的,
  "可读性"的收益被"一致性"的收益盖过。

## 常见质疑与回应

**Q:不用 Lombok 是不是不熟悉?**
> 熟悉,而且知道它的两个坑:`@Data` 在 JPA / MyBatis 实体上生成的 `equals/hashCode` 会把
> 所有字段算进去,懒加载或集合字段会炸;`@Builder` 和无参构造冲突要额外加 `@NoArgsConstructor`。
> 不用它是为了这个项目的读者:Java 弱项的人需要看到 getter / setter 真实存在,才能理解
> MyBatis-Plus 和 Jackson 靠什么反射。不可变的数据我全用 record,这是语言特性,比 Lombok
> 更干净。

**Q:record 和 Lombok 的 @Value 有什么区别?**
> record 是 Java 16 正式的语言特性,编译器直接理解它:自动生成规范构造器、访问器
> (`title()` 不是 `getTitle()`)、equals / hashCode / toString,组件是 final 的,不能加实例字段。
> `@Value` 是注解处理器在编译期生成同样的东西,但 IDE 和其他工具要装插件才认识。
> record 的一个限制是不能继承,但数据类本来也不该继承。

**Q:Spring Boot 3.3 已经过期了,为什么不用最新的?**
> 这是保守选择。3.3 + MyBatis-Plus 3.5.7 是我确定能跑的组合;3.4 以后
> `mybatis-spring` 升到 3.0.4,MyBatis-Plus 那边有过 `factoryBeanObjectType` 类型不匹配的
> 兼容性问题报告。项目的重点是测试体系不是追版本,升级是一个独立的、可验证的动作:
> 改 parent 版本、跑全部测试、看 CI 绿不绿——正好是这个测试体系存在的意义。

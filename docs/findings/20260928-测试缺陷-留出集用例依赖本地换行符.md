# 2026-09-28 测试缺陷 · 留出集离线用例依赖本地工作区的换行符(CI 失败)

> 记录类型:测试自身缺陷(不编 KI 号,KI 只记被测服务的问题)。数据来自 GitHub Actions 的真实运行记录(`gh run view`)与本地复现。

## 1. 现象

2026-09-27 推送 main(45a4852)与三个 tag 后:

`printf ... > tests/allure-results/environment.properties` 报 `No such file or directory`。

## 2. 根因

- `test_source_with_swallowed_code_block_is_refused` 按字节构造"出错的原稿":把 H-004 修正后的内容片段替换成一个空行。片段常量 `H004_FIXED` 写死了 `\r\n`。
- 仓库里的原稿 `tests/llm_security/data/holdout_source.txt` 是 **LF**:`.gitattributes` 为 `* text=auto eol=lf`,1596939 入库时 git 已把原始文件的 CRLF 规范化为 LF
  (`git ls-files --eol`:`i/lf`)。CI 在 Linux 上检出得到 LF,`replace` 一处也没匹配上,`broken == source`,前置断言失败。
- **本地为什么没暴露**:这个文件是用 `git mv` 从仓库根目录的 `工单.txt`(聊天端复制下来的,CRLF)移进来的,之后工作区里的那份从没被 git 重新检出过,
  一直保留着原始的 CRLF(`w/crlf`)——`git status` 显示干净,因为 git 比较时会做同样的规范化。用例在本地读到的是 CRLF,片段恰好匹配。
  这不是 Windows / Linux 的平台差异本身(Windows 上重新检出同样得到 LF),而是"本地工作区副本"与"仓库内容"不一致;和服务无关——这一步是纯离线用例,不起服务、不走挡板也不走真实模型。
- **引入的提交**:cbf37da(`tests(llm_security): 留出集逐字转换为 holdout.jsonl…`,用例首次出现),位于 v0.6 与 v0.7 之间,与 v0.6 成功、v0.7 失败一致。

## 3. 本地复现

1. 删除工作区副本后 `git checkout -- tests/llm_security/data/holdout_source.txt`,`git ls-files --eol` 变为 `i/lf w/lf`(与 CI 相同)。
2. 用修改前的用例文件(HEAD 版本的副本)跑:`1 failed, 9 passed`,失败的正是 `test_source_with_swallowed_code_block_is_refused`,断言相同。

## 4. 修复(只改用例的构造方式,不改断言、不删用例)

- `H004_FIXED` 改为 LF;新增 `_source_with(nl)`:把原稿统一换成指定换行。
- `test_source_with_swallowed_code_block_is_refused` 按 `LF` / `CRLF` 参数化,两种换行下都构造出错原稿、都必须报 `SourceError(H-004)`——比原来多覆盖了一种。
- 新增 `test_conversion_does_not_depend_on_line_endings`(LF / CRLF):转换结果与换行无关。这把"本地 CRLF、CI LF"这种差异本身钉住,以后换行相关的回归在两边都会红。
- 修改后在 LF 检出下跑 CI 同一步(`cd tests/llm_security && python -m pytest`):**176 passed**(原 173 条:该用例 1 → 2 条,新增 2 条)。
- 附带更正:README 里"原稿按原样入库"补一句"仓库内按 `.gitattributes` 存为 LF,原始文件是 CRLF"。内容逐字未变,只有换行符被规范化。
